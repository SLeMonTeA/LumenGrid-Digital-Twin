# LumenGrid 数字孪生正式业务流程测试手册

> 本手册按业务验收顺序编排，覆盖设备模拟、告警与维护、ERP 生产计划同步、MES 开工设备校验、执行绑定、设备异常通知与人工暂停建议、恢复及事件追溯。用于本地演示环境，不代表真实 PLC 或工厂控制验证。

## 1. 测试目标与系统分工

本轮验收要跑通以下闭环：

```text
ERP 审核/下达生产订单
  → LumenGrid 同步生产计划
  → MES 同步工单并按工序工作中心查询设备可用性
  → MES 开工并异步绑定设备
  → LumenGrid 模拟设备采样并触发异常告警
  → Twin 将重要设备状态事件异步通知 MES
  → MES 操作员确认暂停建议，暂停状态再异步回写 Twin
  → Twin 维护设备、恢复模拟并留下事件轨迹
```

- **WarehouseFlow ERP/WMS**：生产订单及工序计划的来源。
- **TraceForge MES**：工序开工、报工和暂停建议的业务操作方；设备异常不会绕过人工自动停工。
- **LumenGrid 数字孪生**：模拟设备、采集指标、生成规则告警、管理维护任务、同步生产计划、记录设备与生产执行事件。

## 2. 服务地址与启动

本机默认地址：

| 服务 | 地址 |
| --- | --- |
| WarehouseFlow ERP API | `http://localhost:6101` |
| TraceForge MES API | `http://localhost:6102` |
| LumenGrid API | `http://localhost:6103` |
| TraceForge MES 页面 | `http://localhost:6173` |
| WarehouseFlow ERP 页面 | `http://localhost:6174` |
| LumenGrid 页面 | `http://localhost:6175` |

在 `D:\Learn\Interview` 下启动全部服务：

```powershell
.\Scripts\start-all.ps1
```

脚本遇到已有监听端口时不会重启对应服务。服务启动后可用以下地址检查 API：

```text
http://localhost:6101/health
http://localhost:6102/health
http://localhost:6103/health
```

每个地址应返回健康状态。然后分别打开 ERP、MES 和 Twin 页面，并确认 Twin 页面右上角显示实时连接。

> 本地启动脚本以 Development 环境运行 API，因此模拟控制入口可用。若独立部署到非 Development 环境，需在 LumenGrid 配置中启用 `Simulation:ControlApiEnabled`。ERP、MES 和 Twin 的集成密钥必须在各自本地配置中一致；不要把真实密钥写进测试记录或提交到 Git。

## 3. 测试前准备

### 3.1 确认设备和工作中心

LumenGrid 初始化数据通常包含以下设备：

| 设备编码 | 工作中心 | 建议用途 |
| --- | --- | --- |
| `LINE-A-01` | `WC-ASSY-A` | MES 开工、异常通知和暂停建议主流程 |
| `LINE-A-02` | `WC-ASSY-A` | 同工作中心的备用设备 |
| `TEST-01` | `WC-TEST-01` | 测试工序可用性演示 |
| `PACK-01` | `WC-PACK-01` | 包装工序可用性演示 |

可在 Twin 设备卡片或 API `GET /api/equipment` 查看当前实际设备。设备匹配按**工作中心完全对应**进行：ERP 工单的工序工作中心、MES 工序工作中心和设备档案工作中心必须一致。主流程优先使用 `WC-ASSY-A` 与 `LINE-A-01`。

### 3.2 检查 MES 与 Twin 集成

1. 打开 MES 生产总览，检查 MES 与 LumenGrid 的集成状态没有持续失败。
2. 打开 Twin 页面“集成状态”，确认 ERP 生产计划和 MES 设备通知通道可见。
3. 如果看到失败计数，先检查三个服务是否都在线、配置的 BaseUrl/集成密钥是否匹配；修复后可使用页面的同步或重试操作。

### 3.3 数据安全和演示环境

- 使用本机演示数据库和演示单据。测试过程会新增告警、维护任务、ERP/MES 事件和执行记录。
- Twin 的“清理场景”只重置设备模拟状态和页面实时信号，不会删除数据库里的告警、维护任务、事件历史、生产计划或执行绑定。
- 不要为追求空白画面随意清空数据库；可以用新的 ERP 生产订单号继续测试。
- 建议先使用 Twin 的“加载演示预置”，它会启动 `LINE-A-01`、`TEST-01`、`PACK-01`，并重置其他设备状态。若当前工序工作中心不是这些设备对应的工作中心，请改选工序或核对设备档案。

## 4. 阶段一：验证设备模拟和实时数据

### 操作步骤

1. 在 Twin 页面点击“加载演示预置”。
2. 等待约 5–10 秒，确认 `LINE-A-01` 状态变为运行中，心跳时间持续更新。
3. 在“模拟信号中心”确认最近批次出现该设备，温度、振动、累计产量有数据。
4. 在设备卡片确认工作中心为 `WC-ASSY-A`，且设备允许接收生产。
5. 在“设备事件时间线”选择 `LINE-A-01` 并点“查看历史”，确认出现设备启动和指标采集事件。

### 预期结果

- 设备由停止/启动中进入运行状态，信号中心定期刷新。
- 事件时间线显示设备启动等记录。
- SignalR 实时连接正常时，状态变化不需要手工刷新页面。

## 5. 阶段二：运行 ERP → Twin 生产计划同步

### ERP 操作

1. 在 ERP 中按现有 ERP 测试手册完成生产订单建立、审核及下达。若沿用已有订单，确认状态仍有效、未取消。
2. 确认至少有一道工序的工作中心为 `WC-ASSY-A`，计划数量大于 0。
3. 记录 ERP 生产订单号和工序工作中心，后续用于 MES 匹配。

> ERP 的菜单和单据流程以当前 ERP 页面及最新 ERP 手册为准；旧版手册中的独立入库/出库执行步骤可能已因流程调整而过时，本次 Twin 验收不依赖这些旧步骤。

### Twin 操作

1. 在 Twin 页面“集成状态”点击 ERP 通道的“立即同步计划”。若自动同步已完成，也可以直接核对。
2. 等待页面反馈同步完成，必要时再次刷新集成状态。
3. 在 Twin 设备事件时间线选择工作中心为 `WC-ASSY-A` 的设备并查看历史，确认出现生产计划同步事件。
4. 通过以下只读接口核对订单号、产品、计划数量、状态及工作中心：

```text
GET http://localhost:6103/api/integration/erp/production-plans?activeOnly=true
GET http://localhost:6103/api/integration/erp/production-plans/sync-status
```

### 预期结果

- 同步状态出现成功记录，失败数为 0。
- 有效 ERP 生产订单在 Twin 快照中可查到，工作中心包含 `WC-ASSY-A`。
- 计划同步是后台轮询与页面手动同步两种触发方式；重复事件会按事件键去重。

## 6. 阶段三：MES 开工并确认执行绑定

### 操作步骤

1. 打开 MES 生产总览，点击“同步 ERP 订单”。
2. 找到刚才记录的工单。若未出现，先核对 ERP 订单已下达、MES ERP 接口配置和 MES 同步状态。
3. 展开/进入工单，选择工作中心为 `WC-ASSY-A` 的工序。
4. 确认 Twin 中 `LINE-A-01` 正在运行、可接收生产；如果工作中心没有可用设备，MES 开工应被拒绝，这是预期保护行为。
5. 在 MES 点击该工序“开工”。
6. 等待约 5–20 秒，让 MES Outbox 后台投递执行绑定。
7. 回到 Twin，检查 `LINE-A-01` 的生产执行上下文、事件时间线或 API：

```text
GET http://localhost:6103/api/integration/mes/execution-bindings
```

### 预期结果

- MES 开工前同步调用 Twin 的设备可用性接口；可用设备通过校验后才会开工。
- MES 页面显示工序执行中。
- Twin 后续收到 `Running` 执行绑定，能够显示关联的 MES 工单、工序及报工上下文。
- 执行绑定是异步 Outbox 投递；“MES 已开工但 Twin 尚未立刻显示”时，先等待一个投递周期，再检查 MES 生产总览上的 ERP/MES 回传失败信息。

## 7. 阶段四：触发告警并完成 Twin 维护闭环

本节以高温场景为例，避免对同一设备同时叠加多个故障场景。

### 操作步骤

1. 在 Twin 的 `LINE-A-01` 设备卡片点击“高温”。
2. 等待温度超过阈值并持续至少 30 秒（默认采样周期约 2 秒；建议等待 35–45 秒）。
3. 在“当前告警”确认出现 `TEMP-HIGH` / 高温告警，并核对设备编码、当前温度和触发时间。
4. 按页面按钮推进告警状态：点击“确认”，再点击“处理中”。也可以直接按当前状态出现的“处理中”按钮。
5. 点击告警上的“建维护任务”。
6. 在“维护任务”区域点击“开始维修”。确认设备状态进入维护、不可接收生产。
7. 点击“完成维修”。当前页面会以 `restoreEquipment=true` 完成维护并恢复设备；等待后续采样周期，设备应重新进入运行状态。
8. 确认告警从活动列表移至“已解决告警”。点击“关闭归档”。
9. 在设备事件时间线查看高温场景、告警、维护开始、维护完成、设备恢复等事件。

### 预期结果

- 默认高温规则：温度大于 `85°C` 且条件持续 `30 秒`。
- 告警产生后不会自动建立维护任务；维护任务由操作员显式创建。
- 维护任务创建/开始时设备不可用于开工；完成维护且选择恢复后，设备模拟回到正常场景。
- 维护完成可自动将关联活动告警标记为已解决；“关闭归档”是单独的告警生命周期步骤。

## 8. 阶段五：验证设备异常 → MES 暂停建议 → 状态回写

这是跨系统主验收项。Twin 只会把选定的重要状态事件写入 MES 通知队列；高温/振动场景切换本身不会通知 MES。为稳定验证“设备异常 → MES 暂停建议”，使用运行中的工序、告警关联维护任务和“开始维修”操作，后者会产生明确的维护开始通知。

### 操作步骤

1. 确认 MES 中存在与 `LINE-A-01` 关联、状态仍为运行中的工序，并且该执行绑定已同步到 Twin。
2. 在 Twin 的 `LINE-A-01` 卡片点击“高温”，等待至少 35–45 秒，直到“当前告警”出现 `TEMP-HIGH`。
3. 在 MES 确认对应工序仍显示运行中；不要先在 Twin 解决告警或完成维护。
4. 在 Twin 对这条告警点击“建维护任务”，随后在维护任务区域点击“开始维修”。设备转入维护状态，且 `MaintenanceStarted` 事件进入 MES 通知队列。
5. 等待 Twin→MES 设备通知 Outbox 投递，建议等待 15–30 秒。
6. 在 MES 生产总览刷新数据，找到关联设备、工单和工序的暂停建议，核对建议内容后点击“接受”。
7. 等待 MES→Twin 执行状态 Outbox 投递约 5–20 秒。
8. 在 Twin 检查执行绑定状态变为 `Paused`，并检查设备/工序关联事件。
9. 回到 Twin，在维护任务区域点击“完成维修”（默认恢复设备），等待设备状态回到运行中。
10. 等待 `MaintenanceCompleted` 恢复通知投递到 MES，确认 MES 能看到恢复事件或更新后的设备状态；告警应转为已解决，可再点击“关闭归档”。

补充检查：可另选一台非维护设备，在 Twin 注入“离线”，确认它变为不可用；用一张新的 MES 工序尝试对应该工作中心开工，应被可用性检查拒绝。当前“离线”场景切换本身不产生 MES 通知，因此这一步只验证开工拦截，不用于验证暂停建议。

### 预期结果与边界

- 设备进入维护后不可接收生产，MES 新的开工请求应失败。
- Twin 将维护开始/完成等重要状态事件写入通知 Outbox，再异步投递到 MES；页面短暂延迟是正常的。
- MES 只在本地存在该设备对应的、已同步且仍为 `Running` 的执行绑定时创建暂停建议。
- 暂停建议必须由 MES 操作员人工接受。**告警或设备离线本身不会自动暂停 MES 工序，也不会控制真实设备。**
- 接受建议后 MES 工序状态先本地更新，再通过 MES Outbox 异步回写 Twin。
- 如果已在阶段四完成维护并使工序执行绑定不再处于运行中，请新建/重新开工一条测试工序后再跑本节；不要把已暂停或已完成的执行当作有效前置条件。

## 9. 阶段六：验证其他告警规则（可选）

### 振动异常

1. 确认设备不在维护中，点击设备卡片“振动”。
2. 等待连续 5 次采样达到阈值。
3. 确认出现 `VIBRATION-HIGH` 告警，默认规则为振动大于 `8 mm/s` 且连续 5 个采样点。
4. 可重复阶段四的确认、维护和归档操作。

### 低产能

- 低产能规则以计划目标产能和 **600 秒窗口**计算，API 重启后需要重新积累样本。该场景不适合快速验收；点击“低产能”后可能要等待完整窗口。
- 测试时需先有匹配工作中心的 ERP 生产计划，并核对设备额定产能/目标产能。若时间有限，可略过此项。

### 设备离线规则

- `DEVICE-OFFLINE` 由心跳超时判断，规则窗口约为一分钟。设备卡片“离线”场景会直接使设备不可用，但该场景切换事件不进入 MES 通知队列；可用它测试 MES 开工拦截。MES 通知闭环请按上一节通过开始维护来触发。

## 10. 阶段七：事件历史与回放

1. 在 Twin 页面时间线选择经历过测试的设备，点击“查看历史”。
2. 确认按发生时间可看到启动、状态变化、场景变更、告警、维护、MES 执行绑定等事件。
3. 点击具体事件，查看事件摘要、来源和载荷详情。
4. 使用“逐条回放”及“下一事件”重建历史状态；需要退出回放时点击“回到实时”。

历史回放只读取并重建历史快照，不会重放真实业务操作，也不会再次向 MES/ERP 发送通知。

## 12. 常见问题排查

| 现象 | 优先检查 |
| --- | --- |
| Twin 页面无法访问或 API 报错 | `/health`、端口监听、API 日志、Vue 的 6175→6103 代理 |
| 模拟控制接口 404 | API 是否运行在 Development；非 Development 检查 `Simulation:ControlApiEnabled` |
| MES 开工提示无可用设备 | 工序工作中心是否精确匹配设备工作中心；设备是否运行、在线、可接收生产；MES 是否连到正确的 Twin 地址 |
| ERP 计划没有同步 | ERP 订单是否已审核/下达且有效；Twin ERP BaseUrl、账号/令牌；点击“立即同步计划”后查看同步状态和错误 |
| MES 开工已成功，Twin 暂无执行绑定 | 等待 Outbox 投递周期；检查 MES 执行回传失败计数、MES→Twin 地址及集成状态 |
| MES 没有出现暂停建议 | 必须先有 Twin 已接收的 `Running` 执行绑定；设备与该绑定编码相同；确认 Twin 产生的是 `MaintenanceStarted` 等会通知 MES 的事件，而非仅注入“离线/高温/振动”场景；等待投递并刷新 MES |
| MES 页面有设备通知但工序未暂停 | 这是预期设计；操作员需在暂停建议上明确接受 |
| 高温/振动按钮点了但没有告警 | 检查采样是否暂停、设备是否进入维护、指标是否超过阈值并满足持续时间/采样次数 |
| 集成状态有失败数 | 检查双方服务、BaseUrl、共享集成密钥；修复后用页面的重试按钮重新投递 |
| 点击“清理场景”后历史仍在 | 正常；此按钮重置模拟状态，不清空业务历史和数据库记录 |

| 集成状态 | `GET /api/integration/status` |

> 接口地址均以 `http://localhost:6103` 为基址。对告警和维护的状态变更优先通过页面操作，避免手工调用时漏填操作人、原因等业务字段。
